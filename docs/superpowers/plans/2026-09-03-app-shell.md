# 앱 셸 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 세 화면을 공통 메뉴바 아래에 두고, 목록이 차지하던 `/`를 메인 페이지에 내주며, 검색을 메뉴바 한 곳으로 모은다.

**Architecture:** 라우트를 먼저 옮기고(1), 그 위에 메뉴바를 얹고(2), 목록이 외부 URL 변경을 따라오게 만든 뒤(3), 마지막으로 검색을 메뉴바로 옮긴다(4). 3을 4보다 먼저 하는 이유는 메뉴바 검색이 목록 화면에서 동작하려면 목록이 URL 변화를 읽을 수 있어야 하기 때문이다.

**Tech Stack:** SvelteKit 2 · Svelte 5 runes · Skeleton UI v5 · Tailwind 4 · Vitest · Playwright

**Spec:** `docs/superpowers/specs/2026-09-03-app-shell-design.md`

## Global Constraints

- Svelte 5 runes(`$state`, `$derived`, `$effect`, `$props`)만 쓴다. Svelte 4 스토어나 `export let`은 쓰지 않는다
- Skeleton UI v5 + Tailwind 4가 이미 설정돼 있다. 클래스는 기존 화면과 같은 방식으로 쓴다
- 데이터베이스는 없다. 상태는 `data/` 아래 JSON이고 `src/lib/server/store/`만 그것을 만진다
- 필터 직렬화는 `$lib/filter`의 `filterToParams`/`filterFromParams`만 쓴다. 두 번째 형식을 만들지 않는다
- 태그는 반복 쿼리 파라미터(`tags=a&tags=b`)다. 쉼표는 구분자가 아니라 태그 내용이다
- `EMPTY_FILTER`는 얼어 있다. 스프레드해서 쓸 때 `tags` 배열을 덮어쓰지 않으면 동결된 배열을 물려받는다
- 커밋 메시지는 Conventional Commits 접두사 + 한국어 본문
- 검증은 매 태스크마다 `npx vitest run`, `npx tsc --noEmit`, `npm run build`, `npx playwright test` 넷 다 돌리고 실제 출력을 붙인다

### Task 3: 목록이 외부 URL 변경을 따라오게 한다

**Files:**

**Interfaces:**

지금 목록은 URL을 **한 번만** 읽어 지역 상태에 담고, 이후로는 지역 상태가 URL로 나가기만 한다. 메뉴바가 URL을 바꿔도 목록이 모른다.

- [ ] **Step 1: 실패 테스트 작성**

`src/routes/recordings/page.svelte.test.ts`의 기존 필터 describe 안에 추가한다.

```ts
  it('외부에서 URL의 q가 바뀌면 목록이 따라간다', async () => {
    // 메뉴바 검색이 이 경로로 동작한다 — 목록이 URL을 한 번만 읽고 말면
    // 메뉴바에서 검색해도 목록이 그대로 남는다.
    const { rerender } = render(Page, { data: pageData([rec('레인'), rec('정류장')]) });

    expect(titles()).toEqual(['레인', '정류장']);

    setSearchParams('?q=레인');
    await rerender({ data: pageData([rec('레인'), rec('정류장')]) });

    expect(titles()).toEqual(['레인']);
  });

  it('자기가 쓴 URL 변경에는 다시 반응하지 않는다', async () => {
    // 필터 → URL → 필터로 도는 루프를 만들면 안 된다. 들어온 값이 지금
    // 필터와 같으면 아무것도 하지 않아야 한다.
    render(Page, { data: pageData([rec('레인'), rec('정류장')]) });

    await getByPlaceholder('제목 검색').fill('레인');
    expect(titles()).toEqual(['레인']);

    // 화면이 쓴 것과 같은 값이 URL에서 다시 들어온다
    setSearchParams('?q=레인');
    expect(titles()).toEqual(['레인']);
  });
```

`setSearchParams`와 `titles`, `pageData`, `rec` 헬퍼는 이 파일에 이미 있는 것을 쓴다. `setSearchParams`가 없으면 이 파일이 `$app/state`를 모킹하는 방식에 맞춰 만든다 — 기존 모킹 코드를 읽고 같은 방식으로 `page.url`을 바꾸는 헬퍼를 추가한다.

`src/lib/components/MenuBar.svelte`의 `<script>`에 추가한다.

```ts
  let { pathname = '/', q = '', onsearch = (_: string) => {} } = $props();

  /**
   * 글자마다 URL을 바꾸면 렌더가 과하게 돈다. 사람이 한 단어를 치는
   * 사이보다는 길고, 다 치고 멈췄을 때 기다렸다는 느낌은 안 들 만큼
   * 짧게 잡았다. Enter는 이 대기를 건너뛴다.
   */
  const SEARCH_DEBOUNCE_MS = 250;

  let draft = $state(q);
  let timer: ReturnType<typeof setTimeout> | null = null;

  // 바깥에서 q가 바뀌면(링크로 직접 진입, 뒤로 가기) 입력에도 반영한다.
  $effect(() => {
    draft = q;
  });

  function schedule() {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;
      onsearch(draft);
    }, SEARCH_DEBOUNCE_MS);
  }

  function commitNow() {
    if (timer) {
      clearTimeout(timer);
      timer = null;
    }
    onsearch(draft);
  }

  $effect(() => {
    return () => {
      if (timer) clearTimeout(timer);
    };
  });
```

마크업의 버튼 묶음 앞에 입력을 넣는다.

```svelte
      <input
        class="input w-48"
        placeholder="제목 검색"
        bind:value={draft}
        oninput={schedule}
        onkeydown={(e) => {
          // 한글 조합 중 Enter는 무시한다 — TagInput과 같은 이유로,
          // 조합 확정과 키 입력이 겹쳐 두 번 들어온다.
          if (e.isComposing) return;
          if (e.key === 'Enter') commitNow();
        }}
      />
```

```svelte
<script lang="ts">
  import '../app.css';
  import { page } from '$app/state';
  import { goto } from '$app/navigation';
  import MenuBar from '$lib/components/MenuBar.svelte';

  let { children } = $props();

  const onList = $derived(
    page.url.pathname === '/recordings' || page.url.pathname.startsWith('/recordings/')
  );

  function search(q: string) {
    const params = new URLSearchParams(page.url.searchParams);
    if (q) params.set('q', q);
    else params.delete('q');

    const qs = params.toString();
    const target = qs ? `/recordings?${qs}` : '/recordings';

    // 목록에 이미 있으면 히스토리를 쌓지 않는다 — 검색어 한 글자마다
    // 뒤로 가기 항목이 생기면 브라우저 뒤로 가기가 쓸모없어진다.
    void goto(target, { replaceState: onList, keepFocus: true, noScroll: true });
  }
</script>

<MenuBar pathname={page.url.pathname} q={page.url.searchParams.get('q') ?? ''} onsearch={search} />

{@render children()}
```
