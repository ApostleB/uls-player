# ULS Player 설계

작성일: 2026-08-31

## 1. 개요

음성 파일을 태그와 날짜로 정리하고 검색·재생하는 로컬 웹 애플리케이션.

애플 음성 메모에서 내보낸 녹음 파일을 가져와 제목·설명·태그를 붙이고, 지정한 포맷으로 일괄 변환해 보관한다. 목록에서 제목·태그·날짜로 걸러내고, 파형이 있는 재생기로 들으며 구간에 북마크를 남긴다.

데이터베이스를 쓰지 않고 JSON 파일로 관리한다.

## 2. 범위

**포함**

- 폴더 경로 스캔과 브라우저 업로드 두 가지 입력 경로
- 애플 `CloudRecordings.db`에서 사용자 지정 제목·녹음 시각 복원
- env로 지정한 포맷(mp3, wav 등)으로 일괄 변환, 원본과 함께 보관
- 여러 항목에 태그를 한 번에 붙이는 일괄 편집
- 제목 검색 · 태그 AND/OR · 날짜 범위 필터
- 파형·구간 반복·배속·북마크를 갖춘 재생기
- 백그라운드 변환 작업 큐와 실시간 진행률

**제외**

- 로그인·권한·다중 사용자
- 데이터베이스
- 음성 인식, 자동 태깅
- 원본 파일 삭제 (기록만 소프트 삭제)

## 3. 기술 스택

| 영역 | 선택 |
|---|---|
| 프레임워크 | SvelteKit |
| UI | Skeleton UI v5 (Tailwind 기반) |
| 오디오 처리 | ffmpeg / ffprobe (시스템 설치본) |
| SQLite 읽기 | `better-sqlite3` (읽기 전용) |
| 저장소 | JSON 파일 |

SvelteKit을 고른 이유는 Skeleton의 네이티브 환경이고, 업로드·변환을 다루는 서버 라우트와 UI를 한 프로세스에서 처리할 수 있어서다.

## 4. 사전 조사 결과

샘플 252개(3.1GB, 총 15.5시간, 평균 3.6분, 최대 32.8분)를 직접 분석해 얻은 사실이다. 설계의 여러 결정이 여기에 근거한다.

샘플 위치: `~/Dev/SIDE_PROJECT/_voice_sample`

### 4.1 `.qta`의 정체

`.qta`는 QuickTime 오디오 컨테이너(`ftyp qt  `)이며, 오디오 트랙 두 개를 담는다.

| 스트림 | 코덱 | 내용 |
|---|---|---|
| 0 | AAC LC, 48kHz, 2ch | 일반 재생용 |
| 1 | `apple_apac`, 48kHz, 4ch | Apple Positional Audio Codec (공간 음향) |

인코더 태그는 `com.apple.VoiceMemos (iPhone Version 26.5)`. 공간 음향으로 녹음된 음성 메모가 `.qta`, 꺼진 상태로 녹음된 것이 `.m4a`로 저장된다. 샘플에는 `.qta` 198개, `.m4a` 54개가 섞여 있다.

**ffmpeg에는 `apple_apac` 디코더가 없다.** APAC 트랙을 명시적으로 지정하면 변환이 실패한다.

```
[aist#0:1/apple_apac] Decoding requested, but no decoder found for: apple_apac
```

샘플 전체의 스트림 구성은 `.qta` = `[0]aac [1]apple_apac`, `.m4a` = `[0]aac`로 일관됐다.

### 4.2 제목이 저장된 위치

제목이 두 군데에 서로 다른 값으로 존재한다.

| 위치 | 값 예시 | 정체 |
|---|---|---|
| 파일 메타 `TAG:title` | 화양동, 왕십리로 5 | 애플이 위치 기반으로 자동 생성한 이름 |
| `CloudRecordings.db` → `ZCLOUDRECORDING.ZENCRYPTEDTITLE` | 레인, 정류장, 빨래 | **사용자가 지정한 제목** |

실제 대조:

```
20260709 223613-AA3B4246.qta  | 파일메타: 화양동    | DB: 레인
20260709 224452-FF90390B.qta  | 파일메타: 화양동    | DB: 정류장
20260710 205635-F764650B.qta  | 파일메타: 화양동 2  | DB: 이미 슬픈 사랑
```

컬럼명이 `ENCRYPTED`지만 평문으로 저장된다. `ZPATH`가 파일명과 그대로 일치하며, **샘플 252개 파일 전부 DB와 매칭됐다.** DB에는 256행이 있고 파일이 없는 4행은 삭제된 녹음이다.

파일 메타의 위치 이름은 버리지 않고 `appleAutoTitle`로 함께 보관한다.

### 4.3 녹음 시각과 길이

녹음 시각은 세 곳에서 서로 일치한다.

- `ZCLOUDRECORDING.ZDATE` — Core Data epoch, `+978307200`으로 unix 변환
- 파일 `TAG:creation_time` — UTC
- 파일명 `YYYYMMDD HHMMSS-XXXXXXXX` — 로컬 시각

길이는 `ZDURATION`에 있다.

### 4.4 처리 비용 실측

4.6분(274초, 19.8MB) 파일 기준.

| 단계 | 소요 | 결과 크기 | 252개 환산 |
|---|---|---|---|
| ffprobe 메타 추출 | 0.02초 | — | 약 5초 |
| mp3 192k 변환 | 2.0초 | 6.3MB | 약 8분 |
| wav 44.1k/16bit/mono | 0.19초 | 23MB | 약 45초 |
| 파형 피크용 PCM 추출 | 0.18초 | 4.2MB (버림) | 약 45초 |
| **항목당 합계** | **2.4초** | | **순차 10분 · 4병렬 2.5분** |

`CONVERT_CONCURRENCY` 기본값 4는 이 측정에 근거한다.

### 4.5 용량 추정

WAV를 원본 스펙(48kHz/16bit/스테레오)으로 뽑으면 15.5시간 × 192KB/s ≈ 10.7GB가 되어 총 15GB에 육박한다. 44.1kHz/16bit/모노 기본값에서는 WAV가 약 2.6GB, 원본 3.1GB와 mp3 약 0.9GB를 더해 총 6.6GB 수준이다.

## 5. 아키텍처

각 모듈은 하나의 일만 하고, `store/` 외에는 파일시스템에 직접 접근하지 않는다.

| 모듈 | 하는 일 | 의존 |
|---|---|---|
| `store/` | `recordings.json` 읽기/쓰기. 원자적 저장과 쓰기 직렬화 | 없음 |
| `apple/` | `CloudRecordings.db`를 읽어 `{파일명 → 제목·녹음시각·길이}` 맵 반환 | 없음 |
| `media/` | ffprobe 메타 추출, ffmpeg 변환, 파형 피크 생성 | 없음 |
| `jobs/` | 변환 작업 큐·워커·진행률 이벤트 발행 | `media`, `store` |
| `routes/` | HTTP 처리와 화면 | 위 전부 |

`store/`가 파일 접근을 독점하는 것이 핵심이다. 나중에 서버로 올리며 DB로 전환할 때 이 모듈만 교체하면 된다.

## 6. 데이터 모델

녹음 하나가 항목 하나이고, 파일 3종은 그 안에 들어간다.

```jsonc
{
  "id": "01JQ8...",                     // 내부 고유 ID. 제목 중복을 허용하는 근거
  "title": "레인",                       // DB ZENCRYPTEDTITLE에서 자동 채움
  "description": "",
  "tags": ["데모", "1절"],
  "recordedAt": "2026-07-09T22:36:13+09:00",
  "durationSec": 274.205,
  "sourceName": "20260709 223613-AA3B4246.qta",  // 중복 감지 키
  "appleAutoTitle": "화양동",            // 파일 메타의 위치 이름
  "files": {
    "original": { "ext": "qta", "bytes": 19801836 },
    "mp3":      { "bytes": 6606028 },
    "wav":      { "bytes": 24117248 }
  },
  "bookmarks": [
    { "id": "bk1", "atSec": 42.5, "endSec": 68.0, "note": "후렴" },
    { "id": "bk2", "atSec": 12.0, "endSec": null, "note": "가사 수정" }
  ],
  "createdAt": "2026-08-31T20:35:00+09:00",
  "updatedAt": "2026-08-31T20:35:00+09:00",
  "deletedAt": null
}
```

**파일 경로는 저장하지 않는다.** `media/<포맷>/<id>.<확장자>` 규칙으로 유도한다. 경로가 데이터에 박히면 폴더를 옮길 때 전부 깨진다.

**파형 피크는 별도 파일**(`data/waveforms/<id>.json`)로 분리한다. 항목당 수천 개 숫자라 `recordings.json`에 넣으면 파일이 수십 MB가 되고 필터링할 때마다 통째로 읽게 된다.

**태그 목록은 저장하지 않고** `recordings`에서 집계한다. 252개 규모에서는 즉시 계산된다.

**북마크의 `endSec`이 `null`이면 지점 북마크**, 값이 있으면 구간 북마크다. 구간 북마크는 재생기의 A‑B 반복과 다르다. A‑B 반복은 저장되지 않는 일시적인 재생 상태이고, 구간 북마크는 항목에 남는 데이터다.

**삭제는 `deletedAt` 소프트 삭제**이며, 목록·필터·태그 집계에서 전부 제외한다. 실제 파일은 남는다.

## 8. 화면과 흐름

화면은 **목록**과 **가져오기** 둘이다. 작업 진행률은 가져오기 안에 들어간다.

### 8.1 가져오기

```
① 폴더 경로 입력 또는 드래그앤드롭
        ↓  (변환 없음 · 약 5초)
② 스캔: ffprobe 메타 + CloudRecordings.db 제목 매칭
        ↓
③ 편집 테이블 — 제목이 자동으로 채워진 상태로 검토·수정
        ↓  [저장 및 변환]
④ 작업 큐 등록 → 진행률 화면 (SSE 실시간)
```

②와 ④를 분리한 것이 핵심이다. 스캔은 읽기만 하므로 5초에 끝나고, 그 시점에 제목이 다 채워진 상태로 검토할 수 있다. 무거운 변환은 검토를 마치고 버튼을 누른 뒤 시작한다. 먼저 변환하고 나중에 태그를 다는 순서였다면 잘못 고른 폴더를 되돌릴 방법이 없다.

**편집 테이블의 각 행** — 제목(자동 채움·수정 가능) · 설명 · 태그 입력 · 녹음시각(읽기 전용) · 길이 · 원본 포맷

**일괄 도구** — 체크박스로 여러 행을 선택해 태그를 한 번에 추가/제거한다. 252개에 하나씩 태그를 다는 것은 현실적이지 않으므로, 날짜순으로 묶어 선택하고 공통 태그를 붙이는 것이 주 사용 경로다.

**중복 감지** — 이미 등록된 `sourceName`은 "이미 있음"으로 표시하고 기본 해제한다. 같은 폴더를 다시 스캔하면 새로 추가된 것만 잡힌다.

**진행률** — 항목별로 대기 / 변환중 / 완료 / 실패를 표시하고, 실패한 것만 골라 재시도한다.

**폴더 스캔 시 `CloudRecordings.db` 처리** — WAL 모드이므로 `.db-wal`·`.db-shm`이 함께 있어야 최신 내용이 보인다. 세 파일을 임시 위치로 복사한 뒤 읽기 전용으로 연다.

### 8.2 목록

상단이 필터바, 가운데가 리스트, 하단이 고정 플레이어다.

**필터**

- 제목 부분일치 검색 — `title`만 대상으로 하며 `appleAutoTitle`·`description`은 검색하지 않는다. 대소문자를 무시한다
- 태그 다중 선택 — AND/OR 토글, 기본값 AND
- 날짜 범위 — `recordedAt` 기준, 시작일과 종료일 모두 포함

세 조건은 서로 AND로 결합한다. 필터 상태는 URL 쿼리에 실어 새로고침해도 유지되고 링크로 남길 수 있게 한다.

**리스트 행** — 제목 · 태그 칩 · 녹음시각 · 길이 · 보유 포맷 배지

행을 클릭하면 하단 플레이어에 로드되고 목록은 그대로 남는다. 재생하면서 계속 필터링하고 다음 항목을 고를 수 있어야 하기 때문이다. 제목·설명·태그는 행에서 바로 수정한다. 여러 행을 선택해 태그 일괄 추가/제거와 일괄 삭제가 가능하다.

### 8.3 플레이어

파형을 클릭하면 그 지점으로 점프하고, 북마크는 파형 위에 마커로 표시된다.

| 그룹 | 기능 |
|---|---|
| 탐색 | 파형 클릭 점프 · 시크바 · ±5초 / ±10초 · A‑B 구간 반복 |
| 음량·속도 | 볼륨 슬라이더 · 음소거 · 배속 0.5~2× |
| 포맷 | 원본 / mp3 / wav 전환(재생 위치 유지) · 포맷별 다운로드 |
| 북마크 | 현재 위치에 마커 추가 + 메모, 마커 클릭 시 점프 |
| 단축키 | `Space` 재생·정지 · `←→` 5초 · `Shift+←→` 10초 · `↑↓` 볼륨 · `M` 음소거 · `B` 북마크 |

포맷 전환에서 재생 위치를 유지하는 이유는 같은 녹음을 mp3와 wav로 비교해 듣기 위해서다. 전환마다 처음으로 돌아가면 비교할 수 없다.

## 9. 변환 파이프라인

항목 하나의 처리 순서.

```
① 원본 → media/original/<id>.<ext> 복사
② ffprobe로 디코딩 가능한 오디오 스트림 인덱스 결정
③ env의 각 출력 포맷으로 변환 (-map 0:a:<idx> 명시)
④ 파형 피크 생성 → data/waveforms/<id>.json
⑤ store에 항목 기록
```

### 9.1 스트림 선택

**②에서 인덱스를 하드코딩하지 않는다.** 세 가지 선택지가 있고 각각 다르게 실패한다.

| 방식 | 결과 |
|---|---|
| `-map 0:a:0` 고정 | 샘플에서는 동작하지만, APAC이 먼저 오는 파일에서 전체 실패 |
| ffmpeg 자동 선택 | 동작하지만 어느 트랙이 쓰였는지 알 수 없음 |
| **ffprobe로 조회 후 명시 매핑** | 결정적이고 검증 가능 |

`apple_apac`이 아닌 첫 오디오 스트림을 찾아 명시적으로 매핑한다. 디코딩 가능한 스트림이 하나도 없으면 그 항목을 실패로 기록한다.

### 9.2 파형 피크

8kHz 모노 PCM을 파이프로 받아 `WAVEFORM_PEAKS` 개 구간의 min/max만 계산하고 버린다. 4.2MB짜리 중간 데이터를 디스크에 남기지 않는다.

### 9.3 작업 큐

저장 버튼을 누르면 작업을 큐에 넣고 즉시 응답한다. 워커가 `CONVERT_CONCURRENCY` 개씩 병렬로 변환하고, 화면은 SSE로 진행률을 받는다. 브라우저를 닫아도 서버에서 계속 진행된다.

동기 변환은 252개에서 10분짜리 요청이 되어 타임아웃으로 깨지고, 결국 대량 이전용 CLI를 따로 만들게 되어 코드가 두 벌이 된다. 프론트에서 청크로 끊는 방식은 진행 상태가 브라우저에 묶여 탭을 닫으면 중단된다. 큐 방식은 252개든 3개든 같은 경로로 동작한다.

## 10. 설정

```ini
DATA_DIR=./data
MEDIA_DIR=./media

OUTPUT_FORMATS=mp3,wav          # 쉼표 구분. 여기 없는 포맷은 만들지 않음

MP3_BITRATE=192k
MP3_SAMPLE_RATE=44100
MP3_CHANNELS=2

WAV_CODEC=pcm_s16le
WAV_SAMPLE_RATE=44100
WAV_CHANNELS=1

CONVERT_CONCURRENCY=4           # 동시 변환 수
WAVEFORM_PEAKS=2000             # 파형 해상도
MAX_UPLOAD_MB=500               # 브라우저 업로드 시 파일 1개당 최대 크기
```

`OUTPUT_FORMATS`에 포맷을 추가하면 그 포맷의 `<FORMAT>_*` 설정을 읽어 변환한다. 포맷별 기본값은 코드에 두고, env는 덮어쓰기만 한다.

원본 복사는 설정으로 열지 않고 항상 복사한다. 참조 모드를 함께 지원하면 재생·재변환·삭제 경로가 전부 갈라지는데, 외장 볼륨이 분리되면 깨진다는 문제까지 안고 가야 해서 값에 비해 비용이 크다.

## 11. 에러 처리

252개 일괄 처리에서 일부 실패는 정상 상황이다. 전부 아니면 전무로 만들지 않는다.

| 상황 | 처리 |
|---|---|
| 특정 파일 변환 실패 | 그 항목만 `failed`, ffmpeg stderr을 `jobs.json`에 보관, 나머지는 계속 |
| mp3 성공·wav 실패 | 성공분 유지, 실패한 포맷만 재시도 |
| 디코딩 가능한 스트림 없음 | 항목을 실패로 기록하고 사유 표시 |
| 서버 재시작 | `jobs.json`의 미완료 작업을 시작 시 복구 |
| 디스크 부족 | 변환 전 예상 용량과 여유 공간 비교, 부족하면 시작 거부 |
| 손상 파일 | 스캔 단계에서 ffprobe 실패 → "읽을 수 없음" 표시하고 제외 |
| `CloudRecordings.db` 없음 | 제목 자동 채움만 건너뛰고 파일명으로 진행 |
| JSON 쓰기 | 임시파일 → fsync → rename, 쓰기는 큐로 직렬화 |

## 12. 테스트

단위·통합 테스트는 Vitest, E2E는 Playwright를 쓴다. 샘플 252개가 확보돼 있어 실제 데이터로 검증한다.

- `apple/` — 실제 DB로 파일명→제목 매핑. `20260709 223613-AA3B4246.qta → 레인` 같은 알려진 정답 케이스를 고정한다
- `media/` — 실제 `.qta`로 스트림 선택 검증. **APAC을 고르지 않는지**가 핵심 단언
- `store/` — 동시 쓰기에서 유실이 없는지, 원자적 저장 확인
- 필터 — 태그 AND/OR, 날짜 경계값, 제목 중복
- E2E — 스캔 → 편집 → 변환 → 목록 → 재생 한 바퀴

테스트 픽스처는 샘플 폴더 전체가 아니라 `.qta` 1~2개와 `CloudRecordings.db` 사본만 저장소에 넣는다. 3.1GB를 git에 넣지 않는다.

## 13. 결정 기록

| 결정 | 선택 | 근거 |
|---|---|---|
| 프로젝트 위치 | 신규 독립 프로젝트 | 기존 치과 사이트와 무관 |
| 스택 | SvelteKit + Skeleton v5 | Skeleton 네이티브 환경, 단일 프로세스 |
| 사용 환경 | 로컬 우선, 서버 전환 대비 | `store/`로 저장소 접근 추상화 |
| 데이터 단위 | 녹음 1개 = 행 1개 | 3배로 늘어난 목록과 중복 표시를 피함 |
| 입력 경로 | 폴더 스캔 + 브라우저 업로드 | 3.1GB 초기 이전과 일상적 추가를 모두 지원 |
| 제목 복원 | 앱 기능으로 내장 | 앞으로도 반복해서 가져올 것 |
| 변환 시점 | 지정 포맷 전부 사전 변환 | 3종 상시 보유 요구사항 |
| 변환 설정 | 포맷별 상세 파라미터를 env로 노출 | 용량과 음질을 상황에 맞게 조정 |
| 작업 처리 | 백그라운드 큐 + SSE 진행률 | 실측 10분은 요청 안에서 처리 불가 |
| 원본 보관 | 앱 저장소로 복사 | 외장 볼륨 분리 시에도 재생 유지 |
| 태그 | 자유 입력 + 자동완성 + 일괄 적용 | 252개 정리 속도 |
| 삭제 | 소프트 삭제 | 3.1GB 원본을 실수로 날릴 위험 제거 |
