# 앱 셸 설계 — 메인 페이지 · 라우트 재편 · 메뉴바

작성일: 2026-09-03

## 1. 개요

세 화면(메인·목록·가져오기)을 공통 메뉴바 아래에 두고, 지금 목록이 차지하고 있는 `/`를 메인 페이지에 내준다. 검색은 메뉴바 한 곳으로 모은다.

이 문서는 UI 개선 요청 여섯 건 중 셸에 해당하는 세 건만 다룬다. 나머지는 11절에 남긴다.

## 2. 범위

**포함**

- 메인 페이지 신설 (`/`)
- 목록을 `/`에서 `/recordings`로 이동
- 모든 화면에 뜨는 메뉴바 (앱 이름 · 메인 · 리스트 · 검색)
- 검색을 메뉴바 하나로 통합하고 필터바에서 제목 검색 입력 제거
- 목록이 URL 변화를 따라가도록 필터 상태 동기화 보정

**제외**

- 메인 페이지의 내용. 지금은 껍데기만 만들고 무엇을 담을지는 따로 정한다
- 목록 테이블 헤더, 파형 드래그 게이지, 파일 경로 표시, 상세정보 화면 (11절)

## 3. 라우트 재편

| 지금 | 바뀜 |
|---|---|
| `/` — 목록 | `/` — 메인 (신설) |
| — | `/recordings` — 목록 |
| `/import` — 가져오기 | 변화 없음 |
| `/api/**` | 변화 없음 |

`src/routes/+page.svelte`와 `+page.server.ts`를 `src/routes/recordings/` 아래로 그대로 옮긴다. 파일 내용은 5절·6절이 요구하는 것 외에는 손대지 않는다.

따라 고칠 곳:

- `src/routes/import/+page.svelte:203`의 "목록으로" 링크 — 메뉴바가 대신하므로 제거한다
- E2E의 `page.goto('/')` 10곳 — 전부 목록을 기대하는 진입이므로 `/recordings`로 바꾼다
- `src/routes/page.svelte.test.ts`, `page.server.test.ts` — 파일 위치를 따라 옮긴다

## 4. 메인 페이지

**껍데기만 만든다.** 앱 이름, 한 줄 설명, 목록과 가져오기로 가는 버튼 둘. 그 이상은 넣지 않는다.

내용을 정하지 않은 채 무언가로 채우면 나중에 실제 요구가 왔을 때 걷어내야 한다. 지금 필요한 것은 "메인이라는 자리가 존재하고 거기서 두 화면으로 갈 수 있다"까지다.

## 5. 메뉴바

`src/routes/+layout.svelte`에 둔다. 지금은 `app.css`를 불러오고 children을 그리기만 하는 껍데기라, 셸의 제자리다. 세 화면 모두에 뜬다.

**구성**

| 위치 | 내용 |
|---|---|
| 왼쪽 | `ULS Player` — 누르면 메인으로 |
| 오른쪽 | `메인` · `리스트` 버튼, 검색 입력 |

현재 페이지에 해당하는 버튼은 눌린 상태로 표시한다. 판단 기준은 `page.url.pathname`이며, `/recordings` 아래 하위 경로가 생기더라도 `리스트`가 활성으로 남도록 접두사로 비교한다.

`/import`는 메뉴바 버튼으로 노출하지 않는다. 가져오기는 목록에서 들어가는 동작이고, 메뉴바에는 요청대로 메인·리스트만 둔다. 가져오기 화면에서도 메뉴바는 보이며 목록·메인으로 돌아갈 수 있다.

## 6. 검색을 한 곳으로

**검색 입력은 메뉴바에만 둔다. 필터바에서는 제목 검색 입력을 뺀다.** 필터바에는 태그 칩과 기간 범위가 남는다.

두 입력이 같은 값을 가리키면 사용자는 어느 쪽이 진짜인지 알 수 없고, 구현에서는 둘을 동기화하는 코드가 생긴다. 이 저장소는 이미 같은 계열의 버그를 겪었다 — 지역 `$state`가 URL 변화를 따라가지 못해 목록이 낡은 채로 남았고, 그 수정이 Task 14의 리뷰 항목이었다. 입력을 하나로 두면 그 문제가 생길 자리가 없어진다.

**동작**

- 메인·가져오기에서 검색하면 `/recordings?q=<입력>`으로 이동한다
- 목록에서 검색하면 이동 없이 `q`만 갱신한다 (`replaceState`, 히스토리를 쌓지 않는다)
- 입력을 비우면 `q`를 URL에서 뺀다

메뉴바는 `filterToParams`/`filterFromParams`가 이미 쓰는 것과 같은 `q` 파라미터를 쓴다. 별도의 직렬화를 만들지 않는다.

**입력 반영 시점** — 글자마다 URL을 바꾸면 렌더가 과하게 돈다. 250ms 디바운스를 두고, `Enter`는 기다리지 않고 즉시 반영한다. 값은 명명된 상수로 두고 왜 이 값인지 주석에 남긴다.

**따라 고칠 테스트** — 필터바의 제목 검색을 없애므로, 그 입력을 겨냥한 기존 테스트가 깨진다. 목록 화면 테스트와 E2E에서 `제목 검색` 플레이스홀더를 찾는 곳이 메뉴바 입력을 보도록 바꾼다. 검색 자체가 사라지는 게 아니라 자리가 옮겨가는 것이므로, 그 테스트들이 확인하던 동작(검색어를 넣으면 목록이 걸러진다)은 그대로 유지돼야 한다.

## 7. 목록의 URL 동기화

지금 목록은 필터를 URL에서 **한 번만** 읽어 지역 상태에 담고, 이후로는 지역 상태가 URL로 나가기만 한다. 메뉴바가 URL을 바꾸면 목록이 따라가지 못한다.

`page.url.searchParams`가 바뀌면 필터를 다시 읽어 지역 상태에 반영한다. 단 자기 자신이 쓴 URL 변경에 반응해 무한 루프를 만들면 안 되므로, 들어온 값이 현재 필터와 실질적으로 같으면 아무것도 하지 않는다.

Task 14가 같은 자리에서 배운 것을 지킨다 — 서버/URL이 소유한 값을 지역 상태로 복사할 때는 양방향을 다 만들어야 하고, 낙관적 갱신을 되돌리지 않도록 비교 후에만 덮어써야 한다.

## 8. 엣지 케이스

| 상황 | 처리 |
|---|---|
| `/`로 들어온 뒤 뒤로 가기 | 메인이 히스토리의 첫 항목이므로 정상 동작. 목록의 `q` 갱신은 `replaceState`라 뒤로 가기가 검색어 사이를 오가지 않는다 |
| `/recordings?q=...` 링크 직접 진입 | `filterFromParams`가 그대로 읽어 필터가 걸린 채로 뜬다. 메뉴바 입력에도 같은 값이 채워져야 한다 |
| 검색어에 `&`·`#`·공백 | `URLSearchParams`가 인코딩한다. 별도 처리를 만들지 않는다 |
| 옮긴 뒤 `/`로 오는 기존 북마크 | 메인이 뜬다. 목록으로 리다이렉트하지 않는다 — 사용자가 의도한 목록이 아니라 이제 메인이 첫 화면이다 |

## 9. 테스트

**단위·컴포넌트**

- 메뉴바가 현재 경로에 맞는 버튼을 활성으로 표시한다 (`/`, `/recordings`, `/recordings` 하위, `/import`)
- 앱 이름을 누르면 메인으로 간다
- 메인이 아닌 곳에서 검색하면 `/recordings?q=`로 이동한다
- 목록에서 검색하면 이동하지 않고 `q`만 바뀐다
- 디바운스 중에는 URL이 바뀌지 않고, `Enter`는 즉시 반영한다
- 목록이 외부에서 바뀐 URL의 `q`를 따라간다 — 이 테스트는 7절의 수정을 되돌리면 실패해야 한다

**E2E**

- 메인 → 리스트 → 가져오기 → 메뉴바로 메인 복귀
- 메뉴바에서 검색해 목록이 걸러지는 것까지 한 번에 확인

기존 E2E의 `/` 진입 10곳을 `/recordings`로 바꾼다. 바꾸는 김에 각 테스트가 실제로 무엇을 확인하는지 다시 읽고, 경로만 고쳐 통과시키지 않는다.

## 10. 결정 기록

| 결정 | 선택 | 근거 |
|---|---|---|
| 목록 경로 | `/recordings` | 내용을 그대로 이르는 이름. `/list`는 무엇의 목록인지 말하지 않는다 |
| 메인 내용 | 껍데기 | 요청이 "페이지만 딱". 채우면 나중에 걷어내야 한다 |
| 메뉴바 위치 | `+layout.svelte` | 이미 셸 역할을 하는 유일한 파일 |
| 메뉴바 항목 | 메인·리스트만 | 요청 그대로. 가져오기는 목록에서 들어가는 동작 |
| 검색 위치 | 메뉴바 하나 | 두 입력이 한 값을 가리키면 동기화 버그가 생긴다. 같은 계열을 이미 겪었다 |
| 검색 URL | 기존 `q` 파라미터 | 필터 직렬화가 이미 있다. 두 번째 형식을 만들지 않는다 |
| `/`로 오는 옛 링크 | 리다이렉트 없음 | 이제 메인이 첫 화면이다 |

## 11. 이 문서가 다루지 않는 것

같은 요청에서 나왔지만 별도로 설계한다.

- **목록 테이블 헤더** — 행이 지금 카드 flex라 열 정렬이 보장되지 않는다. 그리드로 바꾸는 구조 변경이 필요하다
- **파형 드래그 게이지** — 재생헤드 선과 시간 말풍선. 소리는 놓을 때 점프한다(스크러빙 없음)
- **재생 중인 파일의 저장 경로 표시** — 우측 하단
- **파일 상세정보** — 어디서 열리고 무엇을 담을지 아직 정해지지 않았다
