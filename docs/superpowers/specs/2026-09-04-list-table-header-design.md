# 목록 테이블 헤더 설계

## 1. 목표

녹음 목록의 각 열에 이름을 붙인다. 지금은 행마다 열 위치가 어긋나 있어, 헤더를 붙이려면 행 구조를 먼저 정렬 가능한 형태로 바꿔야 한다.

이 문서는 **라벨과 열 정렬만** 다룬다. 헤더 클릭 정렬은 넣지 않는다.

## 2. 지금 상태와 문제

`src/routes/recordings/+page.svelte`의 행은 `li`가 카드이고 그 안이 flex다.

```
[체크박스] [본문(제목/설명/태그 세로 쌓기)] [녹음일자] [길이] [포맷 배지들]
```

본문 칸만 `grow`이고 나머지는 `shrink-0`이라, 각 칸의 폭이 그 행의 내용에 따라 정해진다. 날짜 문자열 길이는 같지만 포맷 배지 개수(`Object.keys(rec.files)`)는 행마다 다르므로, 마지막 칸의 폭이 행마다 달라지고 그 앞 칸들도 함께 밀린다. 열이라는 개념이 성립하지 않는 상태다.

## 3. 열 구성

여섯 열로 잡는다.

| 열 | 내용 | 폭 |
|---|---|---|
| 선택 | 체크박스 | 고정 |
| 제목 | 제목, 그 아래 설명 | 가변(`fr`) |
| 태그 | 태그 칩, 인라인 편집 | 가변(`fr`) |
| 녹음일자 | `recordedAt`의 `YYYY-MM-DD HH:MM` | 고정 |
| 길이 | `fmt(durationSec)` | 고정 |
| 저장된 확장자 | 포맷 배지들 | 고정 |

태그는 본문 칸에서 나와 자기 열을 갖는다. 태그는 이 앱의 핵심 축이라 세로로 정렬돼 훑을 수 있는 값이 크다.

설명은 제목 칸에 남는다. 탐색기의 "이름" 열이 부제를 함께 보여주는 것과 같은 형태다.

## 4. 정렬을 보장하는 방법

열 정의를 CSS 커스텀 속성 하나에 담고, **헤더 줄과 각 `li`에 같은 `grid-template-columns`** 를 적용한다. `li`는 지금처럼 카드로 남아 hover·선택 배경과 행 클릭 동작을 유지한다.

### 지켜야 할 제약

각 행이 **독립된 그리드 컨테이너**다. 따라서 내용에 따라 폭이 정해지는 트랙(`auto`, `min-content`, `max-content`, `fit-content()`)을 쓰면 행마다 계산 결과가 달라져 정렬이 다시 깨진다.

**모든 트랙은 내용과 무관한 값(`fr`, 고정 `rem`)으로만 정의한다.** 특히 저장된 확장자 열이 이 함정에 해당한다 — 파일이 2개인 행과 3개인 행의 자연 폭이 다르므로 반드시 고정 폭을 준다.

가변 열에는 `minmax(0, Nfr)`을 쓴다. `0` 최소값이 없으면 긴 제목이 트랙을 밀어내 정렬이 깨진다.

### 채택하지 않은 대안

`ul`에 그리드를 걸고 `li`를 `display: contents`로 두면 모든 행이 하나의 그리드를 공유해 `auto` 트랙도 쓸 수 있다. 그러나 `display: contents`인 `li`는 박스를 만들지 않으므로 카드 배경·hover·선택 표시가 전부 사라지고, 그 스타일을 셀마다 다시 입혀야 한다. 얻는 것(내용 기반 폭)보다 잃는 것이 크다.

진짜 `<table>` 구조로 바꾸면 의미와 정렬이 모두 정확해지지만, 인라인 편집 마크업 전체를 다시 써야 한다. 이번 범위를 벗어난다.

## 5. 좁은 화면

여섯 열은 좁은 폭에서 뭉개진다. 목록 전체를 `overflow-x: auto` 컨테이너에 넣고 최소 폭을 준다. 페이지 본문 자체는 가로로 스크롤되지 않는다.

## 6. 빈 상태

"조건에 맞는 녹음이 없습니다"·"아직 가져온 녹음이 없습니다" 카드는 그리드 템플릿을 쓰지 않고 전체 폭을 쓴다.

표시할 행이 하나도 없으면 **헤더 줄도 렌더하지 않는다.** 아무것도 없는 위에 열 이름만 떠 있는 상태를 만들지 않는다.

## 7. 접근성

이 목록은 `table`이 아니라 `ul`/`li`다. 시각적 헤더 줄은 셀과 의미적으로 연결되지 않으므로, 스크린 리더에게는 연결 없는 라벨 여섯 개가 떠다니는 것으로 들린다.

각 셀은 이미 자기 내용을 읽을 수 있게 갖고 있다(제목 버튼, 태그 칩, 날짜·길이 텍스트, 포맷 배지). 따라서 헤더 줄은 장식으로 보고 `aria-hidden="true"`를 준다.

`role="table"`/`role="row"`/`role="columnheader"`를 얹어 의미를 만드는 방법도 있으나, 그러려면 행 안의 모든 요소에 `role="cell"`을 정확히 배치해야 하고 인라인 편집 컨트롤이 그 구조 안에서 어떻게 노출될지를 따로 설계해야 한다. 이번 범위에 넣지 않는다.

## 8. 태그 열로 옮겨가는 것들

태그 표시와 인라인 편집이 통째로 새 열로 이동한다.

- 더블클릭으로 편집 진입(`startEditTags`)
- `TagInput` + "완료" 버튼(`commitTags`)
- 행 클릭이 편집으로 번지지 않게 막는 `stopPropagation`
- 편집 중인 행이 필터에서 사라질 때 초안을 저장하는 기존 동작

태그가 많은 행은 그 열 안에서 줄바꿈한다. 열 폭은 고정 비율이므로 태그 개수가 다른 행끼리도 정렬이 유지된다.

## 9. 테스트

"열이 정렬된다"는 눈으로 보는 속성이라, 그대로 단언하려 들면 헛도는 테스트가 되기 쉽다. 정렬 자체가 아니라 **정렬이 성립하는 조건**을 고정한다.

| 대상 | 확인 | 깨뜨리는 뮤테이션 |
|---|---|---|
| 열 정의 공유 | 헤더 줄과 행이 같은 열 정의를 참조한다 | 한쪽 템플릿만 바꾸면 실패 |
| 내용 의존 트랙 없음 | 열 정의에 `auto`·`min-content`·`max-content`가 없다 | 확장자 열을 `auto`로 되돌리면 실패 |
| 헤더 라벨 | 여섯 라벨이 렌더된다 | 라벨 제거 시 실패 |
| 태그 열 분리 | 태그가 제목 칸이 아니라 자기 열에 렌더된다 | 태그를 본문 칸으로 되돌리면 실패 |
| 빈 상태 | 행이 없으면 헤더가 렌더되지 않는다 | 헤더를 무조건 렌더하면 실패 |

기존 태그 인라인 편집 테스트(더블클릭 편집, 일괄 추가·제거, 편집 중 행 이탈 시 저장)는 열이 옮겨간 뒤에도 **그대로 통과해야 한다.** 셀렉터만 고치고 검증 내용은 바꾸지 않는다.

## 10. 이 문서가 다루지 않는 것

- **헤더 클릭 정렬** — 정렬 상태를 URL에 담을지, 기존 필터와 어떻게 섞일지를 따로 정해야 한다
- **파형 드래그 게이지, 재생 중인 파일의 저장 경로** — 재생기 스펙에서 다룬다
- **파일 상세정보** — 별도 스펙. 진입점이 목록 행에 생긴다면 이 그리드 재구성 뒤에 얹는다
