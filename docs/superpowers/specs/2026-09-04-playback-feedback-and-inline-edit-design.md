# 재생 피드백과 인라인 편집 정리 설계

## 1. 목표

목록에서 행을 눌렀을 때 무슨 일이 일어나는지 알 수 있게 한다. 그리고 행 안의 세 인라인 편집(제목·설명·태그)이 같은 규칙을 따르게 한다.

출발점은 하나의 증상이었다 — 행을 눌러도 하단 재생기가 안 뜨고, 클릭이 씹힌 건지 불러오는 중인지 알 수 없어 몇 번씩 누르게 된다.

## 2. 원인: 죽은 클릭 영역

증상의 주된 원인은 피드백 부재가 아니라 **클릭이 실제로 아무 일도 하지 않는 영역**이다.

`src/routes/recordings/+page.svelte`의 행에서 본문 칸(제목·설명)과 태그 칸은 각각 `onclick={(e) => e.stopPropagation()}`으로 행 클릭을 끊는다. 그 안의 컨트롤이 자기 동작을 갖고 있으니 행 선택이 가리지 않게 하려던 것이다. 그런데 실제로는 이렇다.

| 컨트롤 | 가진 핸들러 | 한 번 클릭했을 때 |
|---|---|---|
| 제목 버튼 | `onclick` + `ondblclick` | 행 선택됨 |
| 설명 버튼 | `ondblclick`만 | **아무 일도 없음** |
| 태그 버튼 | `ondblclick`만 | **아무 일도 없음** |

설명은 제목 바로 아래 칸 너비만큼 깔려 있고, 태그는 열 하나를 통째로 차지한다. 행에서 가장 누르기 쉬운 자리들이 죽어 있었다.

## 3. 세 가지 수정

### 3.1 죽은 클릭 영역 제거

설명 버튼과 태그 버튼에 `onclick={() => (selectedId = rec.id)}`를 더한다. 제목 버튼이 이미 쓰는 방식과 같다.

더블클릭 편집은 그대로 유지된다. 첫 클릭이 행을 선택하고, 두 번째 클릭에서 편집이 열린다 — 제목이 지금 그렇게 동작하고 있고 문제가 없었다.

`stopPropagation`은 그대로 둔다. 그것을 없애면 편집 중인 입력창을 클릭할 때도 행 선택이 다시 일어난다.

### 3.2 행을 누르면 재생을 시작한다

지금은 행을 바꿔도 자동 재생하지 않는다. 이것은 의도된 결정이었고 `Player.svelte`에 근거가 주석으로 남아 있다 — "목록을 필터링하며 다음 항목을 고르는 화면 특성상, 행을 클릭했을 뿐인데 소리가 갑자기 튀어나오는 쪽이 더 당황스럽다".

실사용에서 반대로 드러났으므로 **이 결정을 뒤집는다.** 행을 누르는 것은 듣겠다는 뜻으로 본다.

- 다른 행을 누르면 그 녹음을 불러와 재생을 시작한다
- **이미 재생 중인 행을 다시 누르면 아무 일도 하지 않는다.** 처음부터 다시 시작하지 않는다 — 클릭이 먹었는지 몰라 다시 누르는 상황이 이 기능의 출발점인데, 그때 재생 위치가 0으로 튀면 원래 문제보다 나쁘다
- 포맷을 바꾸는 경우는 기존 동작을 유지한다(재생 중이었으면 이어서, 아니면 멈춘 채)

자동 재생은 브라우저 정책에 막힐 수 있다. 사용자의 클릭에서 시작된 재생이므로 정상적으로는 허용되지만, 거부되면 3.3의 오류 표시 경로로 처리한다.

### 3.3 로딩과 오류 표시

`<audio>`에 로딩·오류 이벤트가 하나도 연결돼 있지 않다. 진행 중인지 실패했는지 화면에 나올 길이 없다.

재생/일시정지 버튼 자리에 상태를 표시한다. 그 자리인 이유는 사용자가 이미 보고 있는 곳이고, 로딩 중에 누를 수 없다는 사실까지 같은 자리에서 전달되기 때문이다.

| 상태 | 버튼 자리 |
|---|---|
| 불러오는 중 | 스피너, 비활성 |
| 재생 가능 | 재생/일시정지 |
| 실패 | 오류 표시, 다시 시도 가능 |

**제목은 즉시 나온다.** 불러오는 동안에도 어느 곡을 골랐는지는 바로 보여야, 클릭이 먹었다는 것이 전달된다.

상태 판정은 `<audio>`가 이미 발생시키는 이벤트를 쓴다 — `loadstart`·`canplay`·`error`·`waiting`·`playing`. 별도의 타이머를 두지 않는다.

**늦게 도착한 응답이 현재 선택을 덮지 않아야 한다.** 파형 `fetch`는 이미 `recording?.id === id`로 그것을 막고 있다. 오디오 로딩 상태도 같은 규칙을 따른다 — 빠르게 여러 행을 누르면 이전 녹음의 `error`나 `canplay`가 나중에 도착할 수 있다.

## 4. 인라인 편집 정리

제목·설명·태그가 같은 규칙을 따르게 한다. 태그는 이미 완료 버튼이 있으므로, 제목과 설명을 거기에 맞춘다.

### 4.1 저장 경로는 하나로 둔다

제목·설명은 지금 `onblur`로 저장한다. 여기에 완료 버튼을 그냥 더하면 버튼을 누르는 순간 blur가 먼저 일어나 저장되고, 편집이 닫히며 버튼이 사라진 뒤에 클릭이 도착한다. 결과는 우연히 맞지만 경로가 둘로 갈라진다.

**저장은 `onblur` 한 곳에서만 한다.** Enter와 완료 버튼은 입력창을 blur시키기만 한다. 트리거는 셋, 저장 경로는 하나다.

### 4.2 Enter와 한글 조합

Enter로 저장하되, **조합 중인 Enter는 무시한다.**

이 저장소는 같은 함정에 이미 빠진 적이 있다. `TagInput`에서 "정준일"을 치고 Enter를 누르면 태그가 "정준일"과 "일" 둘로 갈라졌다 — 조합 중 keydown에서 처리해 입력을 비우면, IME가 대기 중이던 마지막 음절을 빈 칸에 확정하고, 조합 종료 후 오는 두 번째 Enter가 그것을 다시 처리했다.

`KeyboardEvent.isComposing`이 참이면 아무것도 하지 않는다. 조합이 끝나면 브라우저가 Enter를 한 번 더 주므로 저장할 기회를 잃지 않는다.

### 4.3 입력창 크기

편집 모드로 들어갈 때 **행 높이가 눈에 띄게 변하지 않는 선**까지 줄인다. 지금은 입력창이 평소 텍스트보다 훨씬 높아, 편집을 시작하면 그 행이 커지고 아래 행들이 밀린다.

제목과 설명 입력창 모두에 적용한다. 한 칸에 위아래로 붙어 있어 한쪽만 고치면 어긋나 보인다.

### 4.4 완료 버튼

제목·설명 편집에 완료 버튼을 둔다. 태그 편집의 완료 버튼과 같은 모양·같은 자리 규칙을 따른다.

## 5. 테스트

| 대상 | 확인 | 깨뜨리는 뮤테이션 |
|---|---|---|
| 죽은 영역 (설명) | 설명을 한 번 클릭하면 그 행이 재생 대상이 된다 | `onclick` 제거 시 실패 |
| 죽은 영역 (태그) | 태그를 한 번 클릭하면 그 행이 재생 대상이 된다 | `onclick` 제거 시 실패 |
| 더블클릭 편집 보존 | 설명·태그를 더블클릭하면 여전히 편집이 열린다 | 기존 테스트가 지킨다 |
| 클릭 시 재생 | 다른 행을 누르면 재생이 시작된다 | 자동 재생 제거 시 실패 |
| 같은 행 재클릭 | 재생 중인 행을 다시 눌러도 위치가 0으로 돌아가지 않는다 | 무조건 재시작으로 바꾸면 실패 |
| 로딩 표시 | 불러오는 동안 스피너가 뜨고 재생 버튼이 비활성이다 | 상태 표시 제거 시 실패 |
| 오류 표시 | 로딩이 실패하면 오류가 보인다 | `error` 처리 제거 시 실패 |
| 늦은 응답 | 빠르게 행을 바꾸면 이전 녹음의 상태가 현재 표시를 덮지 않는다 | id 확인 제거 시 실패 |
| Enter 저장 | 제목·설명에서 Enter를 누르면 저장된다 | Enter 처리 제거 시 실패 |
| 한글 조합 | 조합 중 Enter는 저장하지 않는다 | `isComposing` 검사 제거 시 실패 |
| 완료 버튼 | 완료를 누르면 저장된다 | 버튼 제거 시 실패 |
| 저장 경로 단일 | 완료 버튼을 눌러도 저장 요청이 한 번만 나간다 | blur와 버튼이 각자 저장하면 실패 |

배치나 접근 이름을 재는 테스트는 `app.css`를 직접 import하는 별도 파일에 둔다 — 이 프로젝트의 컴포넌트 테스트는 `+layout.svelte` 없이 페이지를 단독 마운트해 Tailwind가 적용되지 않는다.
