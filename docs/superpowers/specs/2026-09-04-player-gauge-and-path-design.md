# 재생기: 파형 드래그 게이지와 저장 경로 표시 설계

## 1. 목표

두 가지를 더한다.

- **파형 드래그 게이지** — 파형 위에서 커서 위치의 재생헤드 선과 시간을 보여주고, 놓는 지점으로 점프한다
- **재생 중인 파일의 저장 경로** — 지금 재생하는 파일이 디스크 어디에 있는지 재생기 우측 하단에 한 줄로 보여준다

## 2. 지금 상태

`src/lib/components/Waveform.svelte`는 캔버스에 파형을 그리고, 클릭하면 `ratioFromClick`으로 진행률을 계산해 `onseek`를 호출한다. 북마크는 캔버스 위에 버튼으로 겹쳐 있다.

캔버스에는 `role="slider"`, `tabindex="0"`, `aria-valuenow`가 붙어 있지만 **키 핸들러가 없다.** 키보드로 조작할 수 있다고 선언해 놓고 아무 키에도 반응하지 않는다.

`Recording`에는 파일 경로가 없다. `FileEntry`는 `ext`(original에만)와 `bytes`뿐이다. 실제 경로는 서버가 그때그때 조합하는데, 그 조합이 세 곳에 중복돼 있다.

- `src/lib/server/jobs/runner.ts:91` — `path.join(cfg.mediaDir, 'original', ${id}.${ext})`
- `src/lib/server/jobs/runner.ts:126` — `path.join(cfg.mediaDir, spec.name, ${id}.${spec.ext})`
- `src/routes/api/media/[id]/[format]/+server.ts:25` — `path.join(config.mediaDir, params.format, ${rec.id}.${ext})`

## 3. 드래그 게이지

### 동작

| 상태 | 재생헤드 선 | 시간 말풍선 | 진행률 채움 |
|---|---|---|---|
| 평소 | 없음 | 없음 | 현재 재생 위치 |
| 호버 | 커서 위치 | 커서 위치의 시각 | **움직이지 않음** |
| 드래그 중 | 커서 위치 | 커서 위치의 시각 | **움직이지 않음** |
| 놓는 순간 | 사라짐 | 사라짐 | 놓은 위치로 이동 |

호버만으로 선과 말풍선이 나타난다. 누르기 전에 어디로 점프할지 확인할 수 있어 빗나간 클릭이 줄어든다.

### 스크러빙 없음을 눈으로도 분명히 한다

드래그 중 **진행률 채움은 움직이지 않는다.** 소리는 원래 위치에서 계속 나는데 채움이 커서를 따라가면 소리와 화면이 어긋나 보인다. 움직이는 것은 선과 말풍선뿐이고, 채움은 놓는 순간 새 위치로 간다.

### 드래그가 캔버스를 벗어날 때

포인터가 캔버스 밖으로 나가도 버튼을 누르고 있는 동안은 계속 따라간다. 좌우 끝을 넘어가면 0과 1에 고정된다. 캔버스 안에서만 듣는 방식은, 끝 근처를 노리다 살짝 벗어나면 드래그가 조용히 죽어 사용자가 다시 시도하게 만든다.

버튼을 캔버스 밖에서 놓아도 그 지점(0 또는 1로 고정된 값)으로 점프한다. 취소하려면 `Escape`를 누른다 — 그러면 선과 말풍선이 사라지고 점프하지 않는다.

### 시간 말풍선

`m:ss` 형식으로, 현재 재생기의 시간 표시와 같은 형식을 쓴다. 선 위쪽에 붙고, 캔버스 좌우 끝에서는 잘리지 않도록 안쪽으로 밀어 넣는다.

### 북마크 마커와의 관계

북마크 마커는 캔버스 위에 겹친 버튼이다. 마커 위에서 눌러도 끌기 시작하면 마커 클릭이 아니라 드래그로 취급하고, 거의 움직이지 않고 놓으면 기존대로 마커 클릭(그 북마크 지점으로 점프)이다.

"거의 움직이지 않았다"의 기준은 **누른 지점에서 3px 이내**다. 임계값이 필요한 이유는 마우스를 누를 때 손이 1~2px 흔들리는 것이 정상이라서다 — 0px을 기준으로 하면 마커를 클릭하려던 사용자가 의도치 않게 드래그 경로로 빠진다.

사용자에게는 두 결과가 모두 "그 지점으로 점프"라 크게 다르지 않고, 마커를 스치듯 지나며 끄는 동작이 막히지 않는다.

### 키보드

`role="slider"`가 이미 약속하고 있는 것을 구현한다.

| 키 | 동작 |
|---|---|
| `←` / `→` | 5초 뒤로 / 앞으로 |
| `Home` / `End` | 처음 / 끝 |

`aria-valuenow`는 이미 진행률을 반영하고 있으므로 그대로 둔다. 텍스트 입력 중에는 반응하지 않는다 — 재생기에 이미 있는 `isTypingTarget` 판정을 쓴다.

## 4. 저장 경로 표시

### 규칙은 한 곳에만 둔다

이 기능의 전부는 **보여주는 경로가 실제로 여는 경로와 같다**는 것이다. 규칙이 두 벌 존재하면 언젠가 갈라지고, 그러면 화면이 존재하지 않는 경로를 자신 있게 보여준다.

그래서 `mediaFilePath(mediaDir, recordingId, format, ext)`를 **서버 전용이 아닌 공유 모듈**(`src/lib/`)에 둔다. 경로 문자열을 잇기만 하는 순수 함수라 클라이언트에서도 안전하다. 서버는 파일을 열 때 `cfg.mediaDir`를 넘겨 부르고, 화면은 표시할 때 같은 함수를 부른다. 구현이 하나뿐이라 갈라질 수가 없다.

§2에 적은 기존 세 사본도 모두 이 함수로 바꾼다. 넷째 사본을 더하는 것은 이 기능이 정확히 피해야 할 일이다.

`mediaDir`는 목록 화면의 `+page.server.ts`가 **문자열 하나로** 내려준다. 녹음마다 포맷별 경로를 미리 만들어 내려보내지 않는다 — 252개 녹음에 포맷이 셋이면 쓰지도 않을 경로 750개를 매 요청에 실어 보내게 되고, 실제로 필요한 것은 지금 재생 중인 하나뿐이다.

### 표시

재생기 우측 하단, 한 줄. 길면 **가운데를 줄이고** 앞과 파일명을 남긴다(`/Volumes/Storage/…/mp3/a1b2.mp3`). 끝만 남기면 어느 저장소인지 모르고, 앞만 남기면 어느 파일인지 모른다. 전체 경로는 `title` 속성에 넣는다.

재생 중인 녹음이 없으면 아무것도 보여주지 않는다. 포맷을 바꾸면 경로도 그 포맷의 것으로 바뀐다.

복사 버튼, 파인더에서 열기는 넣지 않는다. 요청은 "노출"이고, 상세 정보는 다음 스펙이 맡는다.

## 5. 테스트

| 대상 | 확인 | 깨뜨리는 뮤테이션 |
|---|---|---|
| 호버 표시 | 캔버스 위 호버에 선과 말풍선이 뜨고, 커서 위치의 시각을 보여준다 | 호버 핸들러 제거 시 실패 |
| 스크러빙 없음 | 드래그 중 `onseek`가 호출되지 않는다 | 드래그 중 `onseek` 호출을 넣으면 실패 |
| 놓을 때 점프 | 놓은 지점의 진행률로 `onseek`가 정확히 한 번 호출된다 | 놓기 핸들러 제거 시 실패 |
| 캔버스 밖 드래그 | 좌우 끝을 넘겨 놓으면 0 또는 1로 고정돼 호출된다 | 범위 고정을 빼면 1을 넘는 값이 나가 실패 |
| Escape 취소 | 드래그 중 `Escape`면 `onseek`가 호출되지 않는다 | 취소 처리를 빼면 실패 |
| 키보드 | `←`/`→`/`Home`/`End`가 각각 기대 위치로 `onseek`를 호출한다 | 키 핸들러 제거 시 실패 |
| 마커 클릭 보존 | 마커를 눌렀다 그 자리에서 놓으면 기존대로 그 북마크 지점으로 점프한다 | 마커 클릭 처리를 드래그가 삼키면 실패 |
| 경로 일치 | `mediaFilePath`가 만든 경로와 media API가 실제로 여는 경로가 같다 | 한쪽 규칙만 바꾸면 실패 |
| 경로 줄이기 | 긴 경로가 가운데를 줄이되 앞과 파일명을 남긴다 | 끝만 남기는 방식으로 바꾸면 실패 |

기존 파형 테스트 3개(마커 클릭, `durationSec` 0일 때 마커 클릭 무시, 캔버스 클릭 점프)는 **검증 내용을 바꾸지 않고** 통과해야 한다.

배치를 재는 테스트가 필요하면 `app.css`를 직접 import하는 별도 파일에 둔다. 이 프로젝트의 컴포넌트 테스트는 `+layout.svelte` 없이 페이지를 단독 마운트해 Tailwind가 적용되지 않는다.

## 6. 이 문서가 다루지 않는 것

- **파일 상세정보** — 별도 스펙. 이 문서는 경로 한 줄만 다룬다
- **음원 편집(에코 등)** — 별도 스펙, 아직 설계되지 않았다
- **드래그 중 소리 따라가기(스크러빙)** — 명시적으로 뺀다
- **경로 복사·파인더에서 열기**
